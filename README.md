# joplin-to-obsidian

Скрипт для переноса заметок из [Joplin](https://joplinapp.org/) в [Obsidian](https://obsidian.md/) на основе **RAW-экспорта** Joplin. В отличие от обычного экспорта в Markdown, RAW-формат сохраняет ID заметок, блокнотов и ресурсов, что позволяет корректно восстановить все внутренние ссылки и вложения, а не оставлять их битыми.

## Возможности

- Восстанавливает структуру блокнотов Joplin как папки в vault
- Заметки, изначально написанные в Markdown, переносятся как есть (только чинятся ссылки)
- Заметки в HTML (обычно результат переноса из CherryTree, Evernote и т. п.) конвертируются в Markdown через [markdownify](https://github.com/matthewwithanm/python-markdownify)
- Ссылки Joplin вида `:/<32-символьный-id>` заменяются на:
  - `/attachments/имя_файла` — для картинок и вложений
  - `[[Название заметки]]` — для ссылок между HTML-заметками
  - `/Блокнот/Название.md` — для ссылок между обычными markdown-заметками
- Теги Joplin переносятся в frontmatter (`tags: [...]`)
- Оригинальный HTML каждой такой заметки по умолчанию сохраняется отдельно в `html_originals/` со ссылкой из самой заметки — на случай, если конвертация что-то исказит
- Устойчив к ошибкам: если один файл/заметка не обработались, скрипт печатает предупреждение и продолжает работу с остальными
- Декодирует URL-encoded названия вложений (`%D0%90...`, `+` вместо пробела) и не задваивает расширения файлов
- Все генерируемые пути и ссылки корректно percent-encoded (пробелы, кириллица и спецсимволы не ломают markdown-синтаксис)

## Требования

```bash
pip install markdownify beautifulsoup4
```

Python 3.8+.

## Как получить RAW-экспорт из Joplin

1. Откройте Joplin
2. **File → Export All → RAW - Joplin Export Directory**
3. Выберите пустую папку для экспорта

> Если в Joplin включено сквозное шифрование (E2E), временно отключите его перед экспортом — иначе в файлы попадут нечитаемые зашифрованные данные.

## Использование

```bash
python3 joplin_to_obsidian.py <raw_export_dir> <output_dir> [флаги]
```

Затем откройте `<output_dir>` в Obsidian как vault (**File → Open folder as vault**).

### Флаги

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--keep-html` | выключен | Не конвертировать HTML-заметки в Markdown — оставить исходный HTML как есть внутри `.md` файла (Obsidian сам умеет рендерить HTML-теги внутри markdown-заметок) |
| `--no-attach-html-source` | выключен (т.е. оригинал сохраняется всегда) | Отключить сохранение оригинального HTML-файла в `html_originals/` |
| `--html-source-position=top\|bottom` | `bottom` | Где в заметке вставлять ссылку на оригинальный HTML-файл |

### Примеры

Стандартная конвертация с сохранением оригиналов HTML (поведение по умолчанию):
```bash
python3 joplin_to_obsidian.py ./raw_export ./my_vault
```

Оставить HTML как есть, не конвертируя в Markdown:
```bash
python3 joplin_to_obsidian.py ./raw_export ./my_vault --keep-html
```

Не сохранять оригиналы HTML, ссылку на оригинал — сверху заметки:
```bash
python3 joplin_to_obsidian.py ./raw_export ./my_vault --no-attach-html-source
```

## Структура результата

```
my_vault/
├── Блокнот1/
│   └── Заметка.md
├── Блокнот2/
│   └── Подблокнот/
│       └── Другая заметка.md
├── attachments/
│   └── картинка.jpg
└── html_originals/
    └── Блокнот1/
        └── Заметка.html
```

## Известные ограничения

- **Заметки с невалидным HTML** (например, унаследованным от CherryTree с некорректной вложенностью тегов вроде `<td>` без парного `</td>`) могут отрендериться криво что при конвертации в Markdown, что при сохранении как есть через `--keep-html` — это следствие изначально сломанной разметки, а не самого скрипта. Такие заметки проще поправить вручную после переноса.
- Открытие файла из `html_originals/` по клику в Obsidian может показать пустую вкладку, поскольку Obsidian не умеет рендерить `.html` "из коробки". Кликайте правой кнопкой → **Open in default app**, чтобы открыть в системном браузере — либо поставьте community-плагин вроде **Html Reader**.
- Геометки, напоминания и прочие специфичные для Joplin метаданные не переносятся.
- Папка с файлами ресурсов ищется в `resources/` или `.resources/` рядом с RAW-экспортом; если у вас она называется иначе — переименуйте её перед запуском.
- Слишком длинные пути на Windows: имена файлов обрезаются до ~150 символов с запасом, но если у вас очень глубокая вложенность блокнотов, стоит держать `<output_dir>` ближе к корню диска (например, `C:\obsidian`).
